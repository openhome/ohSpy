## What didn't — the headline lesson

**The WinUI-3-no-`SynchronizationContext` marshalling trap crashed Story 3.2 on the first real invoke, and 356 green tests didn't see it — because the test double (`InlineUiDispatcher`) runs `Post` inline, masking the missing marshalling.**

Root cause (from the Windows event log, `.NET Runtime` 1026): `COMException 0x8001010E` (RPC_E_WRONGTHREAD) at `UIElement.set_Visibility` ← the bound window ← `InvocationPopupViewModel.set_IsInvoking` ← the `InvokeAsync` continuation. WinUI 3 installs no `SynchronizationContext`, so `await InvokeActionAsync(...).ConfigureAwait(true)` resumed on a **thread-pool thread**; setting `Result`/`IsInvoking` there raised `PropertyChanged` off-thread → the window poked `UIElement.Visibility` off-thread → unhandled → process exit. No diagnostic was logged because the crash is in the XAML layer, not the emitter.

This is the **same shape as Epic 2's device-tree bug**: a UI-thread reality that unit tests structurally could not catch. We had even codified "prove it's wired" (Epic 2 Action F) — but the *default test dispatcher itself* was the blind spot. The fix (marshal via `_ui.Post`, `ConfigureAwait(false)`, a `DeferredUiDispatcher` regression test, and the `winui-no-synccontext-marshal-vm` memory) is solid and was applied pre-emptively in 3.3. The durable takeaway: **`InlineUiDispatcher` is a marshalling blind spot** — a sibling of the Action-F class — and async VM paths need a `DeferredUiDispatcher` guard.

Second, smaller: **the single-device test network blocked half the UI smoke.** 3.2 steps 5/6/7 (transport-error styling, device-gone banner, close-mid-invoke) and 3.3 steps 2–5 (numeric NumberBox, off-step rejection, fallback-to-text, loading state) couldn't be exercised — the Sky IGD exposes no `<allowedValueRange>` action and no easy killable second device. Each deferred step has passing Core VM unit tests; only the App-side template/projection is unverified. Parked as standing verification debt against a Linn-DS network / the (now re-sequenced) Story 5.2 adapter switch.

## Key takeaways

1. **Retros are compounding.** Every Epic 2 action item was applied and each prevented or caught a real problem in Epic 3 — most visibly, smoke-per-story (E) caught a process crash that 356 green tests missed.
2. **The test double can be the blind spot.** `InlineUiDispatcher` ran `Post` inline and hid the missing UI-thread marshalling — the next layer of "prove it's wired." Guard async VM paths with `DeferredUiDispatcher` (Action H).
3. **WinUI 3 has no `SynchronizationContext`** — Core VM continuations after `await` resume off-thread; marshal every post-await observable mutation via `IUiDispatcher.Post`. Now durable knowledge (`winui-no-synccontext-marshal-vm`); applies to every async popup VM (4.3, 5.x).
4. **`create-story` reconciliation against shipped code keeps paying off** — every Epic 3 story's epic prose diverged from reality, and catching it pre-dev meant zero rework cycles.
5. **Verification tooling is now the binding constraint, not implementation.** The single-device network blocks UI smoke; Epic 4's eventing makes it worse. Hence the dev adapter override (I) + pulling 5.2 forward.
