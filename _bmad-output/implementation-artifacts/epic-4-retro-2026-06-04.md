## What went well

- **The hardest story in the project shipped clean.** 5.2 rebuilds nearly every subsystem from Epics 2–4. `create-story` reconciliation pre-identified the load-bearing surprises — the A23 transport-factory prerequisite, `DeviceRegistry.Clear()` not existing, and `EventCallbackHost` being unable to restart-after-dispose (so it *also* needs the factory + a re-threaded `ISubscriptionClient.SetCallbackHost`). Each would have been a mid-dev wall; none were.
- **The GENA stack landed in clean layers.** 4.1's raw `NotifyRequest` hand-off seam was consumed unchanged by 4.2 (SID filter + parse) and 4.3 (render). The hand-rolled HTTP/1.1 callback host with its hardening matrix worked first time under the fake-GENA-client test harness (slowloris, flood, oversize).
- **The marshalling discipline (Epic 3 Action H) was applied pre-emptively, not reactively.** 4.3's async paths went through `_ui.Post` from the first draft, guarded by `DeferredUiDispatcher` tests. The 3.2 `RPC_E_WRONGTHREAD` crash class did not recur in Core.
- **Review kept doing real work.** 4.2's TOCTOU/await-loop and 5.2's failed-rebuild limbo (D1) were genuine correctness findings. The D1 "harden the failed state" decision (unconditional partial-scope dispose + null `_adapterScope` + regression test) closed a real limbo path.
- **`create-story` reconciliation caught a change-proposal gap.** Even the corrective story's own Sprint Change Proposal missed 3 identity sites — the story-creation reconciliation against shipped code found them before dev. The methodology caught its own blind spot.

## What didn't — the headline lesson

**A design decision modelled UPnP device identity as `System.Guid`, and 515 green tests never saw the flaw — because every test fixture used an RFC-4122 UUID. The first real Linn device (non-RFC-4122 UDN) hit the app and silently vanished.**

This is deeper than the previous epics' UI-thread bugs. It was not a coding slip — **Architecture Decision 9 itself baked the wrong assumption** ("UUID-keyed registry"), and the whole stack faithfully implemented it: `Guid.TryParse` fails → `SsdpParser.ExtractUuid` returns null → all-zero UDN in the SSDP log → `DiscoveryService` drops the announcement on its `Uuid.HasValue` gate → the device never enters the registry or tree. The UPnP spec says a UDN SHOULD be RFC 4122; the tests honoured the SHOULD; the hardware didn't.

The fix (corrective Story 2-10: UDN string identity everywhere, `OrdinalIgnoreCase`, + Amendment A30) was clean and well-scoped. The durable takeaway: **"SHOULD" in a spec is not "WILL" in the field. Model opaque-string domain values as strings, and test with a real non-conforming value from the actual target hardware** (Action K).

A second pattern is now unmistakable: **three of the four smoke bugs were App-side XAML render failures that only surface with real device shapes.**

- The **struct-binding crash** (`63e2378`) — classic `{Binding Key}`/`{Binding Value}` against `KeyValuePair` structs access-violates WinUI; only appears when the first real NOTIFY renders.
- The **tree "Loading…" snapshot** (`a55ed74`) — an imperatively-set `TreeViewItem.ItemsSource` snapshots the placeholder-only collection at container realisation; the bug lost the layout-timing race **only on a 25-service OpenHome device**, never on Sky's small/fast ones.
- The **no-scroll latest-values panel** (`e5731af`) — only `openhome.org:Product`'s large var set + a big `SourceXml` overflowed the window.

The unit suite tests Core VMs; the App window rendering is structurally invisible to it until smoke — and a happy minimal payload would not have surfaced any of the three. Hence Action L: **smoke new windows against the largest real device, not the first that appears.**

## Key takeaways

1. **A spec "SHOULD" is a field "won't."** Identity modelled as `Guid` against an opaque-string UDN passed 515 RFC-4122-shaped tests and dropped the first real Linn device. Model opaque strings as strings; test with real non-conforming hardware values (Action K).
2. **App-render bugs scale with payload, not happy-path coverage.** Three of four smoke bugs only appeared on large/complex real devices (25 services, Product's `SourceXml`). Smoke against the biggest real device (Action L).
3. **Retros keep compounding.** Every Epic 3 action item was applied (H), validated-by-substitution (I → the real 5.2 menu), or front-loaded (J). The marshalling discipline pre-empted the 3.2 crash class entirely.
4. **`create-story` reconciliation caught its own methodology's blind spot** — it found 3 identity sites the corrective Sprint Change Proposal missed. Reconcile against shipped code, always.
5. **Verification tooling stopped being the binding constraint.** The 5.2 adapter switch turned the Linn-DS network into a first-class in-app capability and cleared the entire standing smoke debt from Epics 3–4 in one keystone run.
