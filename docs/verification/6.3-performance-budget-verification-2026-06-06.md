## A. Install-blocker fix (half B) — headless proof (dev)

- **Option chosen: Option 1 (truly self-contained)** — Project-Lead decision (OPEN-Q #1), 2026-06-06. Rationale:
  matches the D12/PRD goal exactly ("drop the installer on a fresh machine, double-click setup.exe, run ohSpy"
  with **no prerequisite installer, no Admin**); removes the `2.1.3` runtime-version coupling that produced
  `0x80670016`; smaller, lower-risk change (delete bootstrap code + keep config + re-publish).
  - **Rejected alternative — Option 2 (framework-dependent):** keep `Bootstrap.TryInitialize`, drop the
    self-contained flags, and make the InnoSetup installer carry + run `WindowsAppRuntimeInstall-x64.exe`
    (≥ 2.1.3) as a `[Run]` prerequisite. Rejected: larger installer-script change, a per-machine runtime
    install step (possible elevation), and it re-introduces the runtime-version coupling `0x80670016` came from.
- **`Program.cs`:** the framework-dependent `Bootstrap.TryInitialize` / `Bootstrap.Shutdown` calls, the
  `0x80670016` `MessageBoxW` failure path, the `PackageVersion minVersion`, and the
  `Microsoft.Windows.ApplicationModel.DynamicDependency` + `MessageBoxW` P/Invoke plumbing were **removed**.
  `[STAThread] Main` + `Application.Start(_ => new App())` (with its `#pragma warning disable CA1806`) +
  `StartupObject`/`DISABLE_XAML_GENERATED_MAIN` wiring **retained**. App build `-warnaserror` **0/0** bar the
  pre-existing benign **WMC1506** (`MainWindow.xaml:162`, untouched). **Core suite 553 passed / 2 skipped —
  unchanged** (this story touches no Core).
- **csproj:** `WindowsPackageType=None` + `WindowsAppSDKSelfContained=true` + `SelfContained=true` **retained**
  (now real, not a no-op). No csproj change.
- **Architecture amendment A32** records the L1641 correction; the `deferred-work.md` bootstrap-contradiction
  entry is marked **RESOLVED**.

### Farm-backed reproducer evidence (dev, headless — AC-6.3.5)

Both reproducers live in `tests/ohSpy.Soak.Tests/PerformanceBudgetReproducerTests.cs`
(`[Trait("category","soak")]`, **reusing** the Story 6.2 farm primitives — nothing new built in the farm).
Invoked by path, excluded from `ohSpy.sln` + the chaos hook + the quick filter. Run:

```
dotnet test tests/ohSpy.Soak.Tests --filter "FullyQualifiedName~PerformanceBudgetReproducerTests"
```

- **Cold large-SCPD ≤ 2 s** (`ColdLargeScpd_Expand_CompletesWithinBudget_ViaGiantScpdFarmDevice`): drives the
  REAL `ServiceNodeViewModel` lazy SCPD fetch (`IsExpanded=true` → `FetchScpdAsync` → streamed action nodes)
  against the farm's 120-action `GiantScpd` device over loopback, timing the cold expand from first
  `IsExpanded=true` to all 120 action nodes streamed. **Measured: 21 ms (budget 2000 ms); 120/120 actions;
  0 UI-stalls > 1 s; 0 unhandled exceptions.**
- **Sustained chatty-SSDP ≥ 20 adv/s** (`SustainedChattySsdp_BurstLoop_SustainsAtLeast20PerSecond_NoStallsNoExceptions`):
  runs the `DeviceFarm` advertiser at a 25 adv/s burst, measures the achieved rate from live SSDP-log growth.
  **Measured: 21.4 adv/s over a 12.1 s smoke window (≥ 20 floor asserted); 0 UI-stalls > 1 s; 0 unhandled
  exceptions.** The ≥ 30 s window is time-parameterised (`OHSPY_SOAK_BURST_DURATION=00:00:30`).
- **Split stated honestly:** the headless harness asserts ≥ 20 adv/s, 0 UI-thread stalls > 1 s (PumpingUiDispatcher
  tick-gap), and 0 unhandled exceptions. The **"no dropped frames / no UI freeze" eye-test is the Project
  Lead's** on the real `ohSpy.App` — a headless harness cannot judge frame drops (same boundary as 6.2 ⭐#1).
  This is also the **reproducible complement to the deferred 6.1.14** burst (deferred-work.md L13: "needs a
  busier network" — the farm now supplies it reproducibly even when the live LAN cannot).
